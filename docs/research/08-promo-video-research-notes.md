# Promo-video research notes — November 21, 2026

Remotion official renderMedia documentation verifies React composition rendering through Node, inputProps, H.264 codec selection, bounded concurrency, browser rendering, and native encoding binaries: https://www.remotion.dev/docs/renderer/render-media . renderStill verifies isolated frame rendering and layout props: https://www.remotion.dev/docs/renderer/render-still . Recommendation: Remotion + React/TypeScript/SVG with all animation a pure frame function; Chromium rasterizes authored compositions, not product screen recordings. Native encoders are technical output machinery only.

OpenRouter official audio collection currently lists music-specific google/lyria-3-pro-preview and google/lyria-3-clip-preview, alongside conversational openai/gpt-audio and mini: https://openrouter.ai/collections/audio-models . Collection describes Pro full songs and Clip 30-second clips, 48kHz stereo; these are published capability claims, not tested here. The Pro page confirms POST /api/v1/chat/completions and bearer auth but its generic example returns text, leaving the exact music-specific output transport insufficiently established by that page: https://openrouter.ai/google/lyria-3-pro-preview .

OpenRouter audio-output guide confirms POST /api/v1/chat/completions with model, messages, modalities [text,audio], audio voice/format, stream:true; SSE choices[].delta.audio.data contains base64 audio fragments. Example openai/gpt-audio uses pcm16. This confirms general audio, not that conversational speech models generate usable instrumental music or that Lyria shares every speech parameter: https://openrouter.ai/docs/guides/overview/multimodal/audio .

Models documentation distinguishes audio, speech, and transcription; GET /api/v1/models?output_modalities=audio is public discovery and /api/v1/models/user is authenticated account-availability discovery: https://openrouter.ai/docs/api_reference/models . TTS documented separately at POST /api/v1/audio/speech with model,input,voice,response_format and binary response: https://openrouter.ai/docs/guides/overview/multimodal/tts . No account key exists in sandbox, so account access, generation success, duration controls, musical quality, precise BPM/key, limits, and release licensing remain unverified. Cache accepted generation bytes and hashes; never regenerate during rendering. Pure TypeScript PCM synth is the always-available deterministic fallback.

Public model metadata additionally confirms google/lyria-3-pro-preview has text+audio output and serves Chat Completions; supported_voices is null and no duration parameter is advertised. Do not copy a speech voice parameter blindly into Lyria requests or imply an exact music-specific response was exercised: https://openrouter.ai/api/v1/model/google/lyria-3-pro-preview . The official documentation index searched here exposed no dedicated music guide; adapter acceptance therefore needs an authenticated smoke test or stronger model-specific transport documentation.
