The runner writes exactly `modelId`, `status`, and `durationMs` to `evidence/stt/smoke-report.json`, without payloads or transcript content.

The official [audio guide](https://openrouter.ai/docs/guides/overview/multimodal/audio) says Responses accepts `wav`/`mp3` only, while Chat Completions accepts provider-supported format strings. The [chat completion reference](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion), `ChatContentAudio`, specifies `{type:"input_audio", input_audio:{data:base64String, format:string}}`. The adapter uses `POST /api/v1/chat/completions`, `messages`, a `text` content part containing JSON-serialized phrase hints, and an `input_audio` content part with `format:"webm"`. It sends no remote audio URL, data-URI prefix, tools, screenshot, clipboard, or surrounding-text field. Google's [Gemini audio guide](https://ai.google.dev/gemini-api/docs/audio) explicitly lists WebM (`audio/webm`) as supported. End-to-end OpenRouter/provider WebM compatibility remains unverified until smoke runs.

The request is non-streaming, requests `store:false` without promising provider zero-retention, and disables OpenRouter provider fallbacks with `provider.allow_fallbacks:false`. Native fetch has no adapter retry and uses `redirect:"error"` to prevent a second redirected request or key forwarding. The 15-second deadline covers protected-key lookup, request headers, response body parsing, and final handoff. Abort reasons and upstream exceptions/bodies are never included in typed errors. A test may shorten, but cannot extend, the deadline.

The adapter is main-only and self-contained. #15 must inject `getApiKey`; development callers can supply `() => process.env.OPENROUTER_API_KEY`. #10/#14 will call the shared `SttAdapter.transcribe({audio,mimeType,phraseHints,signal})`; #254 can implement the same contract without cloud access. No main entry point or renderer wiring is added here. The transcript validator checks the response envelope, a single complete assistant string, absence of refusal/tool output, nonempty text, and no NUL character. It cannot prove semantic transcription accuracy.

The fixed smoke fixture is synthetic English speech saying “Caret speech transcription smoke test.” It is not activated user audio. It was generated with `espeak-ng -v en-us -s 150 -w /tmp/caret-stt-smoke.wav 'Caret speech transcription smoke test.'`, then encoded with `ffmpeg -i /tmp/caret-stt-smoke.wav -map_metadata -1 -c:a libopus -b:a 32k apps/desktop/scripts/fixtures/stt-smoke.webm`. All live request data stays in RAM; only the three report metadata fields are saved.
