The production catalog is `src/main/models/catalog.ts`. The default is multilingual Whisper `small`; `medium` is the one optional larger model. No model weights are bundled. No renderer input can change a URL, catalog, hash, byte size, host list, or storage directory.

## Pin evidence, retrieved 2026-11-21 UTC

Upstream whisper.cpp's [models README](https://github.com/ggml-org/whisper.cpp/blob/master/models/README.md) identifies [ggerganov/whisper.cpp on Hugging Face](https://huggingface.co/ggerganov/whisper.cpp/tree/main) as the source of pre-converted ggml models. The upstream README's model table contains SHA-1 values; those are **not** the SHA-256 pins used here. Hugging Face's LFS `oid` is the file SHA-256. Its Xet hash/CDN `ETag` is a different identifier and must not be used as the model SHA-256.

Metadata was fetched directly with:

```sh
curl -fsS https://huggingface.co/api/models/ggerganov/whisper.cpp/tree/main
curl -sIL https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin
curl -sIL https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-medium.bin
```

## Main-process integration contract

`ModelManager` is independent of the session machine and whisper.cpp engine. Trusted main-process constructors may inject `userData`, `fetch`, catalog, and host list for fixture tests; production uses `createModelServices(userData)`, which accepts no such renderer-controlled configuration. `start(id, signal)` downloads or verifies an installed model. Concurrent starts share one promise and one writer; the first caller's signal owns the transfer. `cancel(id)` waits for file cleanup. `subscribe(listener)` supplies metadata-only progress events; the validated preload supplies fixed `modelStatus`, `startModel`, and `cancelModel` methods for settings to poll, with only the two production IDs permitted.

Files are written with bounded, sequential disk IO into `<userData>/models/<id>.bin.partial`, fsynced, SHA-256 checked from disk, then atomically renamed. An existing `.partial` from a process crash can resume using Range. One mid-stream transport interruption gets an immediate bounded Range retry; exhausted network errors, graceful truncation, bad metadata, disk errors, cancellation, and hash mismatches remove the partial. A server ignoring Range restarts at zero rather than appending duplicate bytes. A completed crash-left partial is hash-verified and renamed without network access.

A new manager checks existing models on its first status request. **Engine integration must call `getVerifiedPath(id, signal)` immediately before first use after app start**, not trust the `ready` flag or construct a path. This method rehashes even an already verified file, rejects a swapped/corrupted file, deletes it, and never returns a mismatched model. It does not execute models. A hostile local process could change a path after the method returns; this is not an OS-enforced immutable-file lease, and the future engine integration must not cache verification across use.

Tests use a real local HTTP fixture server with a trusted injected transport that maps a synthetic HTTPS catalog URL to loopback. Only that transport addressing is adapted; the manager's validation, redirect logic, Range handling, disk writes, hash checks, progress, and cancellation are not mocked.

Windows packaging/file behavior remains **UNVERIFIED: needs Windows**. The owner waived the #9 ordering gate for BUILDING only; this does not verify the Windows gate. No whisper.cpp engine (#254), settings UI (#257), or session-machine dependency is introduced.
