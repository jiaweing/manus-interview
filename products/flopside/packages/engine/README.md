# Dealing, state, betting and settlement (#30–#32)

Import modules by subpath (`@flopside/engine/dealing`, `/state`, `/shuffle`, `/cards`); there is no barrel. This package is authoritative server rules code, not client state or a transport reducer.

## Data boundary

`MatchState` is plain serializable `{ public, private }` data. `public` contains the roster (stable seat indices and IDs), stacks, street/hand contributions, `inHand`/`folded`/`allIn` flags, hand number, dealer and blind indices, fixed 5/10 blinds, board, street, and actor. `private` contains the complete 52-card permutation, `nextCardIndex`, and seat-indexed hole-card arrays (empty for inactive seats). Neither the complete match state nor its private object may be sent to clients or logged. #37 must project viewer-specific cards and events separately.

No revisions, tokens, room metadata, connectivity, RNG functions or timestamps are stored here. These belong to the room/transport layers; #33 can extend the reducer with an injected clock and deadline without adding ambient time reads.

## Transitions

- `startMatch(seats: readonly SeatInput[], deckSource?: DeckSource): MatchState` validates 2–4 unique nonempty seat IDs, allocates 200 chips to each, and deals hand 1 with dealer index 0. Stacks shown in the returned hand already have blinds deducted; `stack + handContribution` is initially 200 per seat.
- `startNextHand(state, deckSource?): MatchState` preserves settled stacks, rotates to the next positive-stack seat, resets per-hand fields, posts short blinds up to the available stack, and deals anew. **The caller must settle/refund the previous hand first.** It refuses fewer than two funded seats; #34 decides match end/rematch rather than calling this after a bust. Busted seats remain at stable indices with `inHand: false` and no cards. A seat that posts its full stack is all-in but remains `inHand: true` for this hand.
- `advanceStreet(state): MatchState` deals flop/turn/river, resets street contributions and betting-round metadata, preserves total hand contributions/stacks/fold/all-in flags/hole cards, and selects the first eligible postflop actor. River cannot advance; #32 must settle it. It can be called repeatedly for a runout even with `actor: null`.
- `nextActor(state, afterIndex = actor ?? dealerIndex): number | null` scans clockwise **after** the anchor, skipping inactive, folded, all-in, and zero-stack seats. It returns null when none can act; with one eligible seat it may return that same seat after wrapping. **It is order, not betting-round completion.** Use the betting module to close rounds and run out when betting cannot continue.

The betting and settlement modules below compose these lower-level transitions. Deadlines, match termination and rematch remain separate issues. Dealing tests simulate fold/all-in/settlement by editing plain fixture state, not by introducing a production command shortcut.

All transitions leave their input state untouched. Returned states can share unchanged private arrays with previous states; callers must treat reducer states as immutable rather than mutate those arrays. Deck-source cards are cloned at the hand boundary so the caller's fixture cannot mutate an active deck.

## Deal and shuffle

There are **no burn cards**. Hole cards are dealt one at a time clockwise starting left of the dealer, for two rounds, skipping inactive seats. The board then consumes the next 3/1/1 cards. A hand's full permutation is retained privately with a cursor, so every dealt card is accounted for exactly once.

The production default is `productionDeck()` in `shuffle.ts`, which supplies `fullDeck()` to Fisher–Yates. `boundedIndex()` rejects uint32 values in the incomplete high modulo bucket before reducing modulo the current bound. Its default source is `cryptoUint32()` using `node:crypto`'s `webcrypto.getRandomValues`; the Node import makes this a server-only module. There are no ambient configuration/environment selectors, non-cryptographic fallbacks, or stored random sources.

A deterministic `DeckSource = () => readonly Card[]` is injectable **only as a function parameter** to start functions; every supplied deck is checked for a valid complete 52-card permutation. Entropy injection into `boundedIndex`/`shuffleDeck` is likewise a function parameter for isolated shuffle tests, never configuration. **#36+ must gate any deterministic deck wiring in a labeled test deployment behind a test flag, verify the flag is off in the production build, and never accept fixture/deck selection from a client.** This package does not implement that room/deployment gate.

Run `bun test packages/engine/dealing.test.ts` from the product root. Tests cover deterministic 2/3/4-seat orders and blinds, rotation, short blinds, card uniqueness and street counts, purity/JSON shape, rejection boundaries, deterministic distribution smoke checks (not a proof of cryptographic strength), small-deck permutation reachability, production 52-card permutations, and a source scan forbidding non-cryptographic randomness in all engine TypeScript files.

## Betting API (#31)

Import `applyAction`, `legalActions`, `progressBetting` and their types from `@flopside/engine/betting`.

- `applyAction(state, seatIndex, { type, totalTo? }): ActionResult` accepts `fold`, `check`, `call`, `bet`, `raise`, `allin`. Map the protocol's `action` string to `type` at the transport boundary. For bet/raise, `totalTo` is the **total on this street**, not the extra payment. All-in can omit `totalTo` or supply the exact stack-plus-street total. Fold/check/call must omit it. Results are `{ ok: true, state }` or `{ ok: false, state, error: { code, message } }`; errors use `NOT_YOUR_TURN` or `ILLEGAL_ACTION`, and return the original, byte-equal state object. Validation never changes stacks or cards.
- `legalActions(state, seatIndex): LegalActions` returns `{ actions, callAmount, canRaise, minTotalTo, maxTotalTo }`. Each action descriptor is `{ type, minTotalTo?, maxTotalTo? }`. Wager ranges are inclusive safe-integer totals; all-in has equal bounds. When a stack cannot reach a full bet/raise, that bet/raise descriptor also has equal bounds at the exact all-in total: no smaller partial short wager is legal. Top-level bounds describe bet/raise and are null if unavailable; `callAmount` is capped by the stack. Non-actors, inactive/folded/all-in seats and completed hands return an empty action list with zero call amount and null bounds. The HUD must use this output, not recreate poker rules. A sole funded player facing an all-in gets fold/call only (plus all-in if it is a short/exact call); no dry-side-pot raise is offered.
- `progressBetting(state, afterIndex?): MatchState` resolves completion without awarding chips. Actions call it automatically with the acting seat's index. **At new-hand boundaries use `progressBetting(startNextHand(settledState, deckSource))`** to handle blind-only all-ins; omitting the anchor preserves the initial actor. Dealing remains a lower-level API. Completed hands are idempotent here.

Public state adds `currentBet`, `lastFullRaiseIncrement` (10 initially and each new street), and `handStatus: "playing" | "folded" | "showdown"`. Each seat adds `actedThisRound`, `lastActedBet: number | null`, and `raiseAllowed`. Blind posts do not count as voluntary actions. Full raises reset other seats' acted flags and reopen rights. A short all-in leaves the full increment unchanged; a prior actor reopens only when the current wager minus its last acted level reaches that increment. Calling an intermediate short-raise level records a new baseline. Rights and acted fields reset on a new street/hand; completed hands disable raise rights.

`currentBet` retains the nominal preflop bring-in of 10 even when the BB posts a short all-in. While at least two non-folded, non-all-in seats have chips, calls still complete that bring-in and those seats retain their unacted options. Betting closure and actor selection use the **actual maximum street contribution among live (in-hand, non-folded) seats**: an already-acted seat that covers it is skipped. With only one funded contender, only its actual outstanding amount matters, not the nominal bring-in or an unacted flag. Heads-up BB 1 or 3 against SB 5 therefore runs out immediately with no actor; BB 7 against SB 5 offers a call of exactly 2. The same rule applies after folds or short calls leave one funded contender in a 3–4-seat hand. `legalActions` offers nothing for a covered sole contender even before normalization, and `applyAction` rejects rather than allowing a phantom fold/check/call. An all-in call is offered only when the remaining stack does not exceed the real outstanding amount; unmatched posted excess remains unsettled for #32.

For #32: `handStatus === "folded" || handStatus === "showdown"`, with `actor === null`, means ready to settle; `settled` cannot be settled again. `folded` means exactly one non-folded contender; no board runout/reveal is done. `showdown` means a five-card board (all-in runouts automatically deal to river). **Every chip remains in `stack` or `handContribution`, including unmatched excess; the betting module never refunds, awards pots, reveals cards, or starts another hand.** Street advancement clears only street contributions, not hand totals. Settle/refund before starting the next hand.

For #33/#34: timeouts can call the same `applyAction` fold transition with the current actor; deadlines/clock injection and match lifecycle are not stored or implemented here. For #37: the new betting fields and legal-action descriptors contain no private cards, but the full state remains server-owned; project the private split separately. For #43: consume the descriptor list and total-to bounds directly, and send `action` plus `totalTo` only for wagers (or exact all-in).

Run `bun test packages/engine/betting.test.ts`. Deterministic tests cover total-to accounting, rejection purity, full and cumulative short raises, heads-up/3/4-seat complete rounds, BB option, skipping seats, fold endings and all-in runouts, including BB 1/3 already covered by SB 5, the actual BB 7 call difference, and multiway short-blind transitions. Seeded tests inject entropy/decks and play 4,500 random-stack hands across 2–4 seats, mixing broad starting stacks, short blinds with funded opponents, and all-short tables. An independent actual-wager oracle checks that a sole funded actor truly owes chips and that its call/all-in descriptors never include nominal excess. Coverage assertions require short-blind hands and covered all-in runouts in every seat count. The tests also enumerate every integer wager represented by each descriptor, reject adjacent illegal wagers, deep-freeze inputs, assert chip conservation and bound turn counts. These tests are not settlement or transport/privacy integration tests.

## Settlement API (#32)

Import `settleHand(state: MatchState): MatchState` from `@flopside/engine/settlement`. Result interfaces (`HandSettlement`, `SettledPot`, `SeatSettlement`, `ChipPayout`) are exported from `@flopside/engine/state`. The transition is pure and requires `handStatus === "folded" || handStatus === "showdown"`, with `actor: null`. **`settled` is not ready for a second settlement**. It throws for unfinished/already-settled hands, inconsistent contender/status data, incomplete contested boards or invalid chip accounting; rejection never mutates input. It does not normalize unfinished hands automatically. `applyAction` already calls `progressBetting`; call `progressBetting(startNextHand(...))` at new-hand boundaries to handle blind-only all-ins. There is no duplicate runout API.

First, a unique highest contributor receives their contribution above the second-highest contribution as an unmatched refund. **All contributors, including folded seats, count toward that comparison.** Equal maxima have no refund. Then increasing positive contribution tiers construct main/side pots over all contributors, retaining folded chips but excluding folded/inactive seats from eligibility. Each pot is awarded using the evaluator among its eligible seats; a singleton eligible seat wins automatically. A fold-ended hand has exactly one contender and never evaluates any hole cards or draws additional board cards. At contested showdown every non-folded `inHand` seat belongs to the showdown set, not only winners or the highest-contribution seats.

**Odd-chip rule:** for each pot separately, divide its amount into integer equal shares. Award the remainder one chip at a time to tied winners starting immediately left of the dealer and continuing clockwise over the stable seat indices (wrap at the roster end, skip non-winners). `winnerSeatIndices` and `payouts` use this same order; contributors, eligible seats and showdown seats use ascending seat-index order. Suits never break poker ties.

`public.handStatus` now also supports `"settled"`. `public.settlement` is `null` when a hand starts and contains this plain-JSON accounting object after settlement:

```ts
{
  reason: "folded" | "showdown",
  showdownSeatIndices: number[], // empty on a fold win; all contenders at showdown
  refunds: { seatIndex: number, amount: number }[], // at most one unmatched refund
  pots: {
    amount: number,
    contributionLevel: number, // inclusive tier after refund, main pot first
    contributorSeatIndices: number[],
    eligibleSeatIndices: number[],
    winnerSeatIndices: number[], // clockwise odd-chip order
    payouts: { seatIndex: number, amount: number }[]
  }[],
  seats: { // one record per stable seat index, including folded/inactive seats
    seatIndex: number,
    contribution: number, // original total hand contribution before refund
    refund: number,
    payout: number, // gross pot awards, excluding refunds
    netPayout: number, // payout + refund - contribution; can be negative
    finalStack: number // stack immediately before settlement + payout + refund
  }[],
  totalPot: number, // sum of pots after refund
  totalChips: number // sum(stack + handContribution) before == sum(stack) after
}
```

Pots/refunds in this result are **historical awards, not chips still held in escrow**; never add their amounts to settled stacks when counting chips. All seat hand/street contributions and `currentBet` become zero, actor stays null and raise rights are disabled. Stacks contain all chips after settlement. Runtime checks enforce per-pot payout sums, refund-plus-pot accounting and total chip conservation with nonnegative safe-integer stacks/chip totals. `folded`, `allIn`, board and private cards remain historical data for this hand until `startNextHand` resets them.

For **#33**, timeout folds use `applyAction`, then settle only if that leaves `folded`/`showdown`. For **#34**, inspect the settled stacks/result for match completion; if play continues, use `progressBetting(startNextHand(settledState, deckSource))`. `startNextHand` resets `settlement: null`, rotates the dealer and preserves total chips. Settlement itself does not decide match winners or start a new hand. For **#37**, this result contains no hole cards, evaluated ranks or best-five subsets: publish only the private hole cards whose seat indices are in `showdownSeatIndices` (plus the viewer's own cards as otherwise allowed). A fold-ended hand's set is empty, so no foreign hole cards become public. The complete `{ public, private }` state remains server-owned and must still pass through viewer-specific projection.

Run `bun test packages/engine/settlement.test.ts`. Regressions cover the 50/100/150 refund and 150/100 pots, folded chips/ineligibility, multi-tier all-ins, ties/board-play, three-way remainder 1/2 and heads-up odd chips, sole-contender no-card wins, uncalled fold refunds, all-in/blind-only runout, lifecycle reset and invalid boundaries. Every successful fixture checks total chips, exact payouts, eligible winners, final stacks and an independent pot oracle. Seeded injected-PRNG play executes 6,000 hands across 2–4 seats via `startMatch`, random `legalActions`/`applyAction`, `settleHand`, and chained `startNextHand` transitions with unequal stacks. It independently constructs pots by depositing chips at each integer contribution layer, checks deterministic winners/remainder ordering, deep-freezes inputs, and asserts conservation/nonnegative stacks at every transition. This is engine coverage, not transport privacy or browser integration verification.

## Deadline API (#33)

Import from `@flopside/engine/deadline`. `TURN_MS` is exactly `12000`. The existing dealing/betting/settlement APIs and exports remain unchanged and untimed. Server callers should use the clock-aware wrappers consistently rather than mix timed and legacy transitions. The only shared state addition is optional `public.turn`: legacy states may omit it; timed active states have `{ actorIndex, handNumber, street, turnId, deadlineAt }`, and timed completed states have `turn: null`. All values are plain public JSON and contain no private cards. `turnId` increases for each new action turn within the hand (including a repeated actor); `handNumber` distinguishes subsequent hands. It resets at a new hand boundary. A room/match generation must additionally fence callbacks across rematches, which reset hand numbering.

- `startMatchAt(seats, nowMs, deckSource?)` and `startNextHandAt(state, nowMs, deckSource?)` compose dealing → `progressBetting` → settlement if complete → deadline assignment. `startNextHandAt` still requires previously settled/refunded stacks and the caller's lifecycle decision to continue. Blind-only all-ins can return a settled hand with no deadline.
- `applyActionAt(state, seatIndex, action, nowMs): ActionResult` preserves the betting result/error contract. An accepted action automatically progresses betting, settles `folded`/`showdown` hands with a null actor via `settleHand`, and gives the new actor a fresh deadline. Rejection returns the identical input state and does not renew the deadline. Callers must not call `settleHand` again when the wrapper has already produced `handStatus: "settled"`.
- `progressBettingAt(state, nowMs, afterIndex?)` normalizes betting and settles completed hands. Normalization without a new hand/street/actor preserves the existing turn object and absolute deadline.
- `advanceStreetAt(state, nowMs)` is a lower-level street transition: as with dealing's API, callers must have closed the round first. It normalizes the next street and assigns a fresh deadline or settles a runout.
- `assignDeadline(state, nowMs)` attaches a deadline to an untimed eligible actor or a changed actor/hand/street. If the current turn still identifies the actor, it returns the identical state: repeated view derivation or resume cannot reset time. It does not progress betting; use the wrappers at hand/action boundaries. Folded/all-in/inactive seats, covered sole contenders, null actors and completed hands do not receive deadlines.
- `expireTurn(state, capturedTurn, nowMs): { expired: boolean, state: MatchState }` compares **all five** captured identity fields with the current turn, as well as its current actor/hand/street. Before the deadline or for a stale callback it returns `{ expired: false, state }` with the identical input state reference. At or after the deadline it applies **fold, never check**, through `applyActionAt`, and settles if betting ends. A duplicate callback is stale. For a late callback the next turn gets `deadlineAt = nowMs + TURN_MS`, using the injected actual expiry time, not the previous deadline. There is no connection-status parameter or ambient time read. Milliseconds must be nonnegative safe integers; fresh deadline arithmetic must also remain safe.

### Room queue handoff (#34 / #37 / #38)

#34 should inspect the wrapper's already-settled hand and its stacks/result for completion, and use `startNextHandAt` when continuing. To adapt a lifecycle transition returning an untimed new match/hand, normalize with `progressBettingAt` and the injected server time before publishing. Do not normalize reconnect as a new hand or restart its timer. #37 should expose `public.turn` in viewer projections, preserving its absolute timestamp and identity unchanged, while continuing to redact the private object separately.

#38 owns clocks and scheduling: after a queued accepted state mutation, capture `{ ...state.public.turn }` if non-null and schedule for its absolute deadline. Capture the room/match generation too. On callback, enter the **same serialized room mutation queue** as player commands; check the captured generation, read the **latest** state, and call `expireTurn(latestState, capturedTurn, injectedServerNowMs)`. Commit/revise/broadcast only if `expired` is true, then schedule the new turn if present or hand off settled state to lifecycle. Cancel obsolete handles as an optimization; identity validation remains mandatory. A callback that fires early is a no-op and must be rescheduled for the unchanged absolute deadline. At the command boundary, process a due current turn before accepting betting intent so a late command cannot beat an overdue queued timeout. Reconnect, snapshots and connection changes never renew turns. The room adapter is responsible for preventing stale generations from affecting reset/rematched hands.
