`lifecycle.ts` now imports the deadline module (which does not import lifecycle at runtime) and exports `startLifecycleMatchAt`, `advanceMatchAt`, `expireTurnAndAdvanceAt`, and `rematchAt`. The bounded drain settles completed but not already-settled hands, applies expiry/bust/ten-hand lifecycle decisions, deals once per continuing hand, and repeats automatic blind-only runouts through at most hand 10. Valid managed states return a final public result with no turn or a live actor with a deadline. IDs are lifecycle-owned; match IDs survive advancement and each new hand receives one fresh hand ID/deck. New hands use `assignDeadline` for `nowMs + 12000` and reset within-hand turn numbering; unchanged live deadlines and final results are identity no-ops. The untimed implementations and their existing tests are unchanged.

The deadline deal wrappers `startMatchAt` / `startNextHandAt` are documented as non-lifecycle-managed APIs only. They must never replace lifecycle advancement or re-deal a lifecycle-managed hand. Both deadline and lifecycle sections prescribe start via `startLifecycleMatchAt`, accepted `applyActionAt` → `advanceMatchAt`, successful expiry via `expireTurnAndAdvanceAt` (or `expireTurn` → `advanceMatchAt` only when expired), and authorized host `rematchAt`. #39 still records `requestExpiryTermination` without changing a live deadline and supplies latest connected IDs at settlement. #38 owns the authoritative clock, serialized room queue, callback scheduling and room/match-generation fencing, especially across rematches. #45 consumes `public.result` and the unchanged rematch success/error contract. The existing authoritative room-roster rematch behavior, including returning lobby reservations, is retained.
