# Session manager — issue #104

Construct one `SessionManager(config, { clock?, env?, spawn? })` for a server process and share it with transport adapters. This module does not register tools or reference HTTP/MCP connections. A new manager has an empty in-memory registry; IDs and terminal content are not stored durably.

`create({ executable, args?, cwd, cols?, rows?, timeoutMs? })` performs policy-aware spawning and returns `{ sessionId, cursor: "0", state }`, as PRD section 9 specifies. `status(sessionId)` synchronously returns `SessionSummary`; `list()` synchronously returns `{ sessions: SessionSummary[] }`. A summary has exactly `id`, `executable` (policy-resolved executable path), `cwd` (canonical approved directory), `dimensions: { cols, rows }`, `state`, `exitCode`, and `signal`. The last two fields are null before actual exit. Each summary is a detached snapshot, including its dimensions.

Creation reserves one of four live slots before its first await, including in-flight policy validation. Failures release their reservations. Actual process exit updates the basic summary and releases a live slot; `terminating` also counts as live. Unknown IDs throw `TerminalError` with `NOT_FOUND`; exhausted capacity throws `LIMIT` without spawning. The injected spawn test seam is called only by `spawnWithPolicy`, after validation and environment sanitation, never in place of policy.

Defaults are 80 columns × 24 rows and fifteen minutes of runtime. Dimensions are positive integers bounded by 240 × 80. Runtime must be a positive integer and produce a finite, safely representable deadline on the injected clock. `createdAt` and `runtimeDeadline` are stored on the internal `Session`. Runtime enforcement and SIGTERM/SIGKILL remain separate lifecycle work; this module does not implement kill.

## Output, PTY EOF and exit retention — issues #107 and #105

`get(sessionId)` exposes the internal `Session` and native `pty`, not a public tool result. Each record requires an `output: OutputRing`, allocated before spawning. PTY data appends to that same bounded ring even before registration and after child exit; `receivedBytes` separately counts raw input bytes for internal diagnostics. Ingest normalizes via streaming replacement UTF-8 decoding and re-encoding. Ring cursors count only these normalized complete-character bytes, always exactly matching the encoded text returned, including invalid input. `read({ sessionId, cursor, maxBytes? })` synchronously returns `{ output, nextCursor, oldestCursor, headCursor, gap, state }` without waiting for output or process exit. Characters are never split; payload/read bounds, stale gaps and typed cursor errors are documented in [output-ring.md](output-ring.md).

There are two distinct lifecycle events. One `child.exited` observer records actual exit code/signal, changes state to `exited`, releases the live slot exactly once and starts `SessionRetention` from actual process exit. It does **not** finalize the ring. Native `Bun.Terminal.exit` reports PTY EOF/read-error, not subprocess status; `spawnPty` exposes this as `onEof` and `eof`. The EOF callback finalizes the production ring once, after final data, converting a dangling incomplete suffix into one U+FFFD (three normalized bytes). It works before or after child exit, including before Session registration. No input-drain callback, silence, sleep or timeout determines output completion.

The original record and production ring remain readable throughout the five-minute retention window, subject to the sixteen-record cap. Expiry/cap eviction removes only exited records, cancels retention timers and disposes their native resources; running/terminating records are protected. EOF, retain and removal are idempotent. Reads of removed IDs return `NOT_FOUND`. See [session-retention.md](session-retention.md) for scheduling/eviction details. Resize and input delegate to their existing services below. Waits, kill and MCP tool adapters remain separate work.

The issue-named `test/session-registry.test.ts` is imported by an integration wrapper so both the exact issue verification command and `bun run test` execute it. Tests use isolated temporary roots, real native PTYs, synchronous summary assertions, instrumented concurrent spawn counts, and a fresh Bun-process lookup fixture. Every spawned PTY/process is awaited and cleaned up, and the suite runs `ps` against only its recorded PIDs to check for surviving live processes.

## Resize — issue #109

`resize(sessionId, { cols, rows })` synchronously returns exactly `{ cols, rows }`. The service lives in `src/sessions/resize.ts`, which exports the single Zod dimension schema shared with creation. Both bounds are inclusive: columns 1–240, rows 1–80. Creation retains its 80×24 defaults; resize requires both dimensions and never coerces non-numbers. Invalid dimensions throw typed `LIMIT` before native resize. Unknown IDs throw `NOT_FOUND`; terminating or exited sessions throw `NOT_RUNNING`, including an exited native child whose record has not yet updated.

On success the service calls `Bun.Terminal.resize(cols, rows)` before publishing the new dimensions to status/list. The returned object and summaries are detached snapshots. A native failure leaves metadata unchanged. No MCP tool is registered by this module.

`bun test apps/server/test/terminal-resize.test.ts` runs the issue-named verification; its integration wrapper also includes it in `bun run test`. An independent Python child asserts its controlling PTY, observes `os.get_terminal_size()` before/after resize, and handles real `SIGWINCH`. Tests cover 120×40, inclusive 1×1 and 240×80 creation/resize, invalid dimensions on both axes, missing resize dimensions, zero native calls on rejected attempts, unknown/non-running sessions, and status/list snapshots. Every child is killed only through its owned PID/process group if still alive, awaited, and checked for leaks under `/proc`.

## Input — issue #108

`write({ sessionId, text?, keys? })` delegates to `writeSessionInput` after the same retention-aware lookup used by status and resize. The input service validates and encodes requests, enforces the 16,384-byte cap, and serializes writes independently per session without resending accepted bytes. Unknown or expired IDs produce `NOT_FOUND`; terminating, exited, or closed sessions produce `NOT_RUNNING`. See [session-input.md](session-input.md) for the exact key vocabulary, acceptance semantics, and real-PTY test coverage. This delegation does not change resize, output counting, actual-exit observation, or retention behavior.
